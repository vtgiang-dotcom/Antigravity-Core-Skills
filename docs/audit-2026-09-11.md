## 2. Findings & Remediation

### F1 — Version deploy sinh ra sai (Cao)

`tools/deploy.py` đọc `fallback-version` trong `pyproject.toml` để đóng dấu `.harness.lock`, nhưng giá trị vẫn là `4.1.0` trong khi `agent.yaml` đã lên `4.2.0`. `tools/garden.py` so sánh hai số này, nên project vừa deploy bị báo drift ngay.

Bằng chứng (sinh lock vào thư mục tạm trước khi sửa): `[NEW] .harness.lock — generated (v4.1.0, 54 shared paths)`.

Sửa: bump `fallback-version` lên `4.2.0`.

### F2 — `.harness.lock` gốc ở format cũ (Cao)

File gốc chỉ có `[harness]` và `[boundaries]`, liệt kê `.github`, `.vscode`, `tools` như harness nguyên khối, và vẫn mô tả engine `jcode`. Template chuẩn sinh ra `[shared_files]` và tách `shared_dirs`. `AGENTS.md` dặn agent đọc `[shared_files]`, nhưng mục đó không tồn tại trong lock gốc. Không test nào kiểm tra lock gốc.

Sửa: viết lại lock theo format hiện tại — 8 harness dir, 3 shared dir, 69 shared path (file harness được git theo dõi), 18 file gốc, ghi rõ jcode đã retired.

### F3 — Template lock lệch khỏi data model deploy (Cao)

`HARNESS_LOCK_TEMPLATE` là chuỗi tĩnh, không ràng buộc gì với `ROOT_FILES`, `EXCLUSIVE_HARNESS_DIRS`, `SHARED_DIRS`. Hệ quả: `.opencode` (cả một engine dir) thiếu khỏi `dirs`; `opencode.json`, `eslint.config.js`, `.env.template` thiếu khỏi `files`. Mọi lock deploy ra đều nói với model rằng đó là code dự án được phép sửa.

Sửa: thêm `.opencode` và ba file còn thiếu. Thêm 4 test ràng buộc template với data model và lock gốc với `fallback-version`.

### F4 — Tham chiếu jcode còn sót trong file ship (Trung bình)

`jcode` retired ở v4.1.0 nhưng còn trong `.env.template` (block FreeModel/OPENAI_* không nơi nào dùng), `init.sh` (nhãn rulebook), `claude-env.ps1` (comment).

Sửa: gỡ cả ba.

### F5 — File lạc `.opencode/opencode.json` (Trung bình)

Config plugin-list cục bộ, chưa từng được track. Config thật là `opencode.json` ở gốc. Đã thêm vào `.gitignore` gốc, không xoá file.

### F6 — Boundary audit báo nhầm skill asset (Thấp)

`.github/scripts/boundary_audit.py` chỉ cho phép một tập extension cố định, không có `.xml`. Skill `mcp-builder` ship `example_evaluation.xml` ở cả 4 mirror, nên mỗi lần chạy audit đều có 4 warning.

Sửa: cho phép `.xml` **chỉ khi** đường dẫn đi qua thư mục `skill/`/`skills/` — không nới allowlist toàn cục, vì làm vậy sẽ làm mù audit với XML lạc. Thêm `tools/test_boundary_audit.py` (8 test).

### F7 — Lệnh test tài liệu hoá không chạy được (Thấp, môi trường)

`.venv` được tạo bằng uv, chỉ chứa một editable install của chính harness, không có `pytest`. `VIRTUAL_ENV` trỏ vào `.venv` nên `python` trên PATH phân giải vào đó, khiến `python -m pytest` báo `No module named pytest` và cả `make test` lẫn `verify.sh` fail. Shim `pytest.exe` mồ côi của Python 3.10 (không hề được cài) chạy ra exit 1 không output, càng gây nhầm.

Sửa hai phần: cài `pytest` vào `.venv`; khai báo `[project.optional-dependencies] dev = ["pytest>=8.0", "ruff>=0.6"]` (runtime deps vẫn rỗng) và cập nhật hướng dẫn trong `CONTRIBUTING.md`.

### F8 — Tài liệu `--bare` sai (Thấp)

`claude-env.ps1` đã chuyển full mode thành mặc định cho mọi profile từ 2026-08-08, giữ `--bare` làm opt-in. `README.md` và `.env.template` vẫn mô tả gateway profile chạy qua `--bare`, khiến người đọc tưởng hooks và auto-memory tắt mặc định.

Sửa: cập nhật cả hai.

### F9 — Số engine sai trong CONTRIBUTING (Thấp)

`CONTRIBUTING.md` ghi ba engine (OpenCode, Kilo Code, Gemini), thiếu Claude Code và GitHub Copilot. `AGENTS.md` và `.harness.lock` đều ghi năm.

Sửa: sửa thành năm engine.

### F10 — Test lifecycle flaky do dùng state thật (Trung bình)

Bốn test trong `tools/test_claude_hooks.py` ghi fixture thẳng vào outbox handoff và `.solocode/` thật của repo rồi khôi phục thủ công. `.claude/hooks/session_start.py` phân giải mọi thứ từ `Path.cwd()`, nên khi chạy full suite chúng tranh chấp state dùng chung: hai test fail ở lần chạy này, pass ở lần sau dù không đổi code.

Sửa: `_run` nhận thêm `cwd`; cả bốn test dựng fixture dưới `tmp_path` và truyền `cwd=tmp_path`. Bỏ hẳn cơ chế backup/restore thủ công.

Bằng chứng: `test_claude_hooks.py` chạy 3 lần liên tiếp — 40 passed mỗi lần; full suite 2 lần liên tiếp — 496 passed mỗi lần.
